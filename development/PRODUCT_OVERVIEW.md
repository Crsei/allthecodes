# allthecodes 产品介绍

> 一个高性能、全平台、功能最全的 AI 编程助手 —— 万物皆可编码。

---

## 一、产品介绍

### 一句话概括

**allthecodes 是一个用 Rust 构建的、运行在本地终端与浏览器中的全功能 AI 编程助手 —— 它像一位永不疲倦的高级工程师，能直接在你的开发环境中理解代码、执行命令、修复问题，让你的每一个想法变成代码。未来还将成为你整个开发团队的调度中枢，统一分发所有 coding CLI 任务，让 AI 全面接管重复性工作，实现真正的「一句话驱动全流程」。同时为你打造一个沉浸式开发环境——有音乐、有游戏化任务、有成长体系、有新手引导——让你不只是"用工具"，而是"生活在里面"。**

### 四大核心功能

#### 1. 🚀 Coding Agent Harness —— 把模型变成能交付的软件工程系统

最近 AI 编程圈越来越多地用 **harness** 来描述真正决定 agent 能力的那一层：不是单个模型，也不是一个聊天框，而是包在模型外面的工程系统——上下文、工具、权限、记忆、验证、观测、调度与人机协作。allthecodes 的核心定位就是一个本地优先的 **coding agent harness**：把大模型接入真实开发环境，让它能安全、可见、可验证地完成软件工程任务。

它不是一问一答的聊天工具，而是自主决策的编码 agent。你给出目标，它会理解意图、规划步骤、调用工具、执行命令、修改代码并验证结果。

| 你告诉它 | 它做的事 |
|---------|---------|
| "这个 TypeScript 报错了，帮我修" | 读取错误 → 定位文件 → 搜索类型定义 → 修复代码 → 运行验证 |
| "给这个 API 加个缓存层" | 理解代码结构 → 设计缓存方案 → 修改多个文件 → 运行测试 |
| "帮我重构这个模块" | 分析依赖关系 → 拆分子模块 → 更新引用 → 确保编译通过 |

**一次任务 = 自主决策链 × 多工具协同**，而不是等着你逐行提示。

从 harness 视角看，allthecodes 把以下能力组合成一个可运行的工程闭环：

| Harness 层 | allthecodes 的能力 |
|-----------|-------------------|
| **上下文层** | 文件读取、全文搜索、git-aware 搜索、上下文压缩、记忆与任务状态 |
| **工具层** | 50+ 内置工具，覆盖文件、Shell、搜索、Web、LSP、Chrome、Computer Use 等真实操作 |
| **执行层** | Bash / PowerShell / PTY 支持、超时控制、进程组管理、后台作业 |
| **扩展层** | MCP 客户端、插件系统、Skills 系统，把第三方工具和团队知识接进来 |
| **协作层** | Agent 分叉/委派、监督者模式、团队协作、任务创建与跟踪 |
| **安全层** | Auto / ACD / Bypass 三种权限模式，工具级别 + 沙箱级别控制 |
| **反馈层** | LSP 诊断、测试/构建结果、事件审计日志、OpenTelemetry、Langfuse 集成 |

这也是它和普通 AI 编程助手的关键差异：**模型只是大脑，harness 才是手、眼睛、记忆、权限系统和反馈回路**。所有工具都在本地直接执行，不经过云端代理，没有中间服务，因此在数据安全、执行速度和可审计性上都有本质优势。

#### 2. 📱 **全平台统一体验 —— 终端、Web、App，全部覆盖**

> 未来路线图：allthecodes 不是一个"终端工具"或"网页工具"——它是一套统一的 AI 编程平台，**移动端、PC、服务器三端一体**，通过 App / Web / 终端（TUI + CLI）三种形态无缝接入。

无论你在哪、用什么设备、在什么场景下开发，allthecodes 都以同一个后端、同一份会话、同一个 Agent 为你服务：

```
┌──────────────────────────────────────────────────────┐
│                  同一个 allthecodes 后端                │
│  (Rust 引擎：Agent、工具、记忆、任务调度)                 │
└──────────────────────────────────────────────────────┘
              ↕            ↕            ↕
        ┌─────────┐ ┌──────────┐ ┌──────────────┐
        │ 💻  PC   │ │ 📱 移动端 │ │ 🖥️  服务器    │
        │         │ │          │ │              │
        │ 终端 TUI │ │ App      │ │ Headless CLI │
        │ Web UI  │ │ Web PWA  │ │ Daemon 服务   │
        │ CLI CLI │ │ 小程序?   │ │ API 网关      │
        └─────────┘ └──────────┘ └──────────────┘
```

| 形态 | 目标用户 | 典型场景 | 功能覆盖 |
|------|---------|---------|---------|
| **🖥️ 终端 TUI** | 专业开发者、资深工程师 | 日常编码、沉浸式开发、CI/CD 集成 | < 5ms 启动，全键盘操作，50+ 工具全量 |
| **🌐 Web UI** | 全栈开发者、团队协作 | 浏览器远程开发、图形化操作、团队看板 | 16 个功能页面，文件/看板/用量/群聊等完整界面 |
| **📱 App（未来）** | 移动开发者、值班 on-call | 查看构建状态、代码审查、紧急修复、学习 | 核心通知 + 轻量操作 + 学习模式 |
| **🖥️ 纯 CLI** | DevOps、脚本自动化 | 管道模式、CI/CD pipeline、自动化任务 | `-p "prompt"` 单次执行，JSON 结构化输出 |
| **⚙️ Daemon 服务** | 团队、企业 | 后台常驻，API 对外暴露，团队协作枢纽 | HTTP API + 团队记忆 + 任务调度 + 多 Agent 服务 |

**统一体验的核心要点：**

```
一次配置，随处运行
  └─ 在 PC 上配好 Provider → 手机上直接可以查看进度
  └─ 在办公室开了会话 → 回家通过 Web 继续
  └─ 开发机上的 Agent → 推送通知到手机 App

同一个 Agent，同一个上下文
  └─ 在任何端上发起任务 → 在其他端上查看实时进度
  └─ 会话、记忆、设置全端同步
  └─ 在服务器上跑 CI → 在手机上收到"编译失败"通知 → 在 PC 上修复

每个端做它最擅长的事
  └─ PC 终端：做深入编码、重任务
  └─ 手机 App：查看状态、做轻量 review、学习
  └─ 服务器 Daemon：跑后台任务、对外服务
```

**为什么三端统一是必须的？**

因为开发者的工作场景从来不是单一的：
- 你在工位上用 PC 写代码
- 出差时用笔记本或平板远程
- 排队时想看看 CI 跑得怎么样了
- 下班了但生产环境出了问题
- 你在写代码，队友在做 review，服务器在跑 CI

allthecodes 不只是一台机器上的工具——它是**跟着你跑的个人开发中枢**。

#### 3. 🔄 **CLI 任务调度中心 —— 让 AI 驱动你的整个工具链**

> 未来路线图：allthecodes 不只自己做任务，还要成为你所有 coding CLI 任务的统一调度中枢。

开发者日常工作中大量时间花在重复性的 CLI 操作上：编译→测试→lint→部署→代码审查→文档生成→依赖更新→基准测试……这些任务分散在不同的工具链中，每次都需要手动执行。

allthecodes 的未来版本将实现：

| 能力 | 说明 |
|------|------|
| **CLI 任务适配器** | 自动发现和适配项目中的 CLI 工具（编译器、包管理器、lint、测试框架、CI 脚本等），建立任务清单 |
| **智能任务分发** | 根据任务类型、优先级、依赖关系，自动编排执行顺序，并行独立任务、串行依赖任务 |
| **分布式执行** | 将任务分发到本地或远程执行节点，支持多机并行编译、分布式测试等场景 |
| **任务缓存与增量** | 缓存已执行的任务结果（类似 build cache），只有输入变化时才重新执行 |
| **失败自动修复** | 任务执行失败时，AI 自动分析日志、定位原因、尝试修复并重试 |
| **流水线编排** | 可视化定义任务流水线（类似 GitHub Actions / GitLab CI 的编排能力，但本地执行） |
| **一键接入现有工具链** | 不需要为每个 CLI 工具写插件，allthecodes 直接调用你的现有工具（make、cargo、npm、webpack、pytest……） |

**典型场景：**

```
你一句话 → "帮我做完这个 PR 的所有检查"

allthecodes 自动调度:
  ┌─ 1. cargo build           (并行的编译检查)
  ├─ 2. cargo fmt --check     ─┐
  ├─ 3. cargo clippy          ├── (这三项可以并行)
  └─ 4. cargo test            ─┘
       │
       ├─ 5. 如果失败 → 读取错误日志 → 定位问题 → 修复代码 → 回到步骤 1
       │
       └─ 6. 全部通过 → "你的 PR 检查全部通过，这是报告..."
```

这不是取代你的工具链，而是**调度你的工具链**。allthecodes 做中间层，让你的现有工具更智能、更自动、更高效。

##### 👶 完全新手模式 —— 让学习开发变成"有人带"

> 最怕的不是"不会"，是"不知道哪里不会"和"出了问题不知道怎么问"。

allthecodes 的完全新手模式（Complete Beginner Mode）是为编程初学者和转行者设计的"保护 + 引导 + 教学"三位一体环境：

| 新手模式能力 | 说明 |
|-------------|------|
| **🔒 沙箱保护** | 文件操作自动备份，误删/误改一键还原，像"游戏存档"一样开发 |
| **🧭 每一步都有解释** | Agent 执行每个操作前，用一句话解释"我为什么这么做"，而不是默默执行完 |
| **💡 主动教学** | 检测到你在做"新手容易踩坑"的操作时，主动提示最佳实践：<br>"你正在手动管理状态——这个项目建议用 Zustand，要不要我帮你配置？" |
| **🔍 错误翻译器** | 把晦涩的编译器/运行时错误翻译成大白话，并给出可操作的修复步骤 |
| **📚 上下文学习** | 当你问"这个怎么写"时，Agent 不只是给答案，还告诉你为什么这么写、相关文档在哪 |
| **🚦 渐进式复杂** | 一开始只展示最简界面（输入框 + 回复），随着你熟悉逐步解锁高级功能（多 Panel、命令行、分布式） |
| **🛡️ 防破坏模式** | `git rm -rf`、`DROP TABLE`、`rm -rf /` 等危险操作 → Agent 自动拦截并解释风险 |
| **🧩 项目脚手架** | "帮我建个 React 项目" → 不但建好，还附带每个文件的作用说明、整体架构讲解 |

**新手模式 vs 普通模式 对比：**

```
同一个操作 "帮我加个登录功能"

普通模式:
  Agent 直接写代码 → 创建 auth 文件 → 修改路由 → 配置 middleware → "搞定了"

新手模式:
  Agent 先解释: "我先看一下你项目里的认证方案……我建议用 NextAuth.js，
                因为你的项目是 Next.js，NextAuth 是最常用且最安全的方案。"
  Step 1: "先安装 next-auth 包 → npm install next-auth（安装中...）"
  Step 2: "创建 `[...nextauth].ts` 路由文件，这是 NextAuth 的入口"
  Step 3: "配置 Provider（我推荐 GitHub OAuth，因为简单安全）"
  → 每一步都问你"理解了吗？" → 你可以问"为什么用这个不用那个"
  → 最终回复附带: "这是完整的登录流程图 → [图]，相关文档 → [链接]"
```

**新手模式的目标：让第一次使用 AI 编程助手的人，2 小时内写出第一个可运行的项目，并且理解每一行代码的作用。**

#### 5. ⚡ **Eco Boost 模式 —— 省 Token、省 CPU、省时间**

> 未来路线图：不是简单省，而是「该省省该花花」的智能调度。

AI 编程助手最大的隐形成本：Token 浪费和无效计算。每次让大模型分析整个代码库、每次对简单任务也调用最强模型、每次重复分析未变化的上下文——都是白花 Token 和算力。

allthecodes 的 **Eco Boost 模式** 是一套方法的集合，根据任务难度和上下文自动选择最优执行策略：

| 策略 | 效果 | 典型场景 |
|------|------|---------|
| **模型分级调度** | 简单任务→低成本模型，复杂任务→最强模型，自动降级/升级 | 修一个变量名用 Gemini Flash，架构重构用 Claude Opus |
| **上下文剪枝引擎** | 自动识别当前任务相关的代码片段，丢弃无关上下文，保持窗口紧凑 | 改一个函数时只加载该函数及直接依赖，不加载整个文件 |
| **增量分析缓存** | 缓存代码 AST 和类型信息，只有变更部分才重新分析 | 大型 monorepo 中，每次修改不重复解析未变部分 |
| **工具调用优化** | 合并连续同类操作，减少 API 往返次数 | 10 个文件替换 → 一次工具调用完成，而不是 10 次 |
| **本地推测执行** | 并行推理可能的下一步操作，预取上下文到本地缓存 | 用户还在输入时，agent 已经在后台做预分析 |
| **任务结果缓存** | 相同 CLI 任务结果缓存（类似 ccache），不重复执行 | 两次编译之间未改代码 → 直接返回前次结果 |
| **CPU 亲和性调度** | 根据任务类型绑定特定 CPU 核心，减少上下文切换 | 编译任务跑在大核上，后台任务跑在小核上 |

**Eco Boost 综合收益估算：**

```
常规模式:   100 Token / 任务 × 1000 任务 = 100,000 Token → 💰 
Eco Boost:  35 Token / 任务 × 1000 任务 =  35,000 Token → 💰💰💰 (节省 65%+ Token)
            CPU 使用降低 40-60%
            时间缩短 50-70%（猜测执行 + 并行调度）
```

这不是单一优化，而是一整套策略的组合。你不需要手动配置——Eco Boost 模式会根据当前上下文、任务复杂度和可用模型自动选择最优组合。
