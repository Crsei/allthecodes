## 一、总览与本期关键判断

### 1.1 主线判断

整个 23 期简报贯穿的主线是：**Coding Agent 正在从"能不能生成代码"进入"可治理、可观测、可进入 CI/CD、执行链可审计"的工程运行时阶段**。

跨期反复出现的产品信号可以归纳为五件套正在成型：

1. **会话管理**：session snapshot、rewind、worktree-aware session、background agent 状态机、session export、revert dock
2. **工具发现**：MCP tool search、registry、skill stats、组织级 marketplace 治理、code mode MCP adapter（默认隐藏 `execute`）
3. **权限治理**：参数级权限规则、命令安全分类器、MCP 信任边界、CI token scope、MDM 托管设置、Agentic Workflow Injection taint tracking
4. **成本观测**：AI credits、cost center、per-session budget、Cost Trace（按 goal/team/role/surface 拆分）、per-user budget、review latency/cycles、AI credit pool
5. **执行链安全**：setup-chain safety、supply-chain gate、secret scanning extended metadata、transcript 防篡改、worktree 删除安全、telemetry manifest

少数关键量化信号：

- **Cursor 数据**：AI 生成代码在没有单独人工 review 的情况下进入生产的比例，从 2026 年初约 7% 上升到 5 月中旬的 36.3%。（覆盖：6/28、6/29、6/30、7/2、7/4）
- **1.8 亿 Git 仓库扫描研究**：单一 bot-account lookup 只能恢复 28,154 个 Claude Code commits，多方法检测识别出 850,157 个，bot-account 仅覆盖约 **3.3%**，每月 commit-attributed agent commits 超过 320,000 个。（覆盖：6/24、6/25、6/26、6/27、6/28、6/30、7/1、7/2、7/3、7/4）
- **OpenAI/Columbia/Duke/UPenn Codex 使用研究**：2026 年上半年 Codex 活跃用户增长 **超过 5 倍**；超过 **10%** 用户每周某时点管理 3 个或更多并发 Codex agents；**26.6%** 使用 skills；需要 8 小时以上人类工作量的复杂任务请求比例显著上升。（覆盖：6/26、6/27、6/28、6/30、7/1）
- **Microsoft 早期 rollout 研究**（7/1 论文）：Claude Code 和 GitHub Copilot CLI 采用者合并的 PR 大约比反事实情形多 **24%**；作者强调 merged PR 只是产出 proxy，不等于真实业务价值。（覆盖：7/3、7/4、7/5、7/6、7/7、7/9）
- **Gartner 预测**（TechRadar 6/25 援引）：AI coding tools 的成本可能在 **2028 年超过平均开发者薪资**；token discipline 不会自然出现，需要组织治理。（覆盖：6/27、6/28、7/9）
- **降本案例**：GitHub Copilot code review 复用 CLI/SDK 内置的 `grep/rg/glob/view` 工具替代旧自定义探索工具，成本降约 **20%**（覆盖：6/26、6/27、6/28、6/29、7/4）；Claude Code `/code-review` 把 5 个 cleanup finders 合并为 1 个，token 使用下降约 **25%**（覆盖：6/30、7/1）。
- **Agentic Workflow Injection 研究**（7/6、7/7 论文）：分析 13,392 个真实 agentic workflows，报告 **519 个潜在 AWI 漏洞，其中 496 个在其威胁模型下确认可利用，精度 95.6%**；issue body、PR description、comments 进 prompt 或 downstream script 形成 Prompt-to-Agent / Prompt-to-Script 风险。（覆盖：7/6、7/7、7/8、7/9）
- **AI chat 与 commit 关系研究**（7/6 论文）：分析 1,356 个 OSS 仓库 / 13,360 个 AI conversation sessions / 79,172 条用户消息，几乎所有 AI chat session 后续都跟随 commits；开发者愿意分享 AI chat 的比例为 **68%**，担忧包括显得不专业、增加 reviewer burden、暴露想法给竞争者。（覆盖：7/7、7/9）
- **Anthropic 诉 Alibaba 蒸馏事件**（Tom's Hardware 7/5 报道）：Anthropic 称 Alibaba 自 2026 年 4–6 月用 **25,000 个假账号 / 28.8M 次交换**非法蒸馏 Claude；7/3 Alibaba 禁用 Claude Code；Reuters 7/8 + WSJ 7/9 报道中国官方对 Claude Code 发出"backdoor"安全警告。（覆盖：7/5、7/8、7/9）

## 二、主流 Coding Agent 产品动态

> 本章节按产品组织，每节末尾标注"覆盖日期"，指 18 期简报中提及该产品的所有日期。

### 2.1 GitHub Copilot 生态

#### 2.1.1 Copilot CLI 新终端界面 GA

**核心**：2026-06-23 GA。终端内支持 issues、PRs、gists tabs；可以 `/mcp add`、`/mcp search`、`/skills`、`/plugin`、`/settings` 在终端内配置 MCP、skills、plugins 和设置；issue/PR 引用可直接插入 prompt。

**意义**：终端从"命令执行窗口"升级为 **GitHub 上下文 + MCP 工具发现 + agent 会话控制** 的入口。

**覆盖日期**：6/24、6/25、6/26。

#### 2.1.2 Copilot App BYOK

**核心**：2026-06-23 GA。可接 OpenAI、Azure OpenAI、Microsoft Foundry、Anthropic、LM Studio、Ollama，以及任意 OpenAI-compatible endpoint。模型出现在 model picker，可按 session 选；密钥存放在本地 OS keychain，UI 不读回。

**意义**：coding agent 产品形态进入"frontier + local + enterprise gateway 混合使用"，单一模型绑定继续弱化。

**覆盖日期**：6/24、6/25、6/26、6/27、6/28。

#### 2.1.3 Copilot CLI Auto Model Selection

**核心**：2026-07-01 GA。按"实时模型可用性、可靠性、推理需求、代码生成复杂度、bug 诊断难度、工具编排需求"等维度自动选模型；用户仍可用 `/model` 手切；管理员策略优先；Auto 会沿自然 cache boundary 路由，降低缓存成本；付费用户使用 Auto 时模型 multiplier 享 10% 折扣。

**意义**：模型选择从"用户手动选"升级为 runtime scheduler 职责。

**覆盖日期**：7/1、7/2、7/3、7/4。

#### 2.1.4 Copilot CLI 进 GitHub Actions

**核心**：2026-07-02 起，Copilot CLI 在 GitHub Actions 中可直接使用内置 `GITHUB_TOKEN`，不再需要长期 PAT；workflow 只需 `copilot-requests: write` 权限。组织仓库运行时，AI credits 计入组织。GitHub 建议配合 cost centers、usage dashboards、session limit 控制成本。

**意义**：coding agent 正式进入 CI/CD。可触发自动修复失败测试、生成迁移补丁、补文档、自动 review、issue triage。但同时也把 agent 放进更敏感的 runner/token/secrets 环境。

**覆盖日期**：7/3、7/4。

#### 2.1.5 Copilot Agent Session Streaming（public preview）

**核心**：2022-07-02 推出。Enterprise Cloud 客户可通过 streaming endpoint 或 REST API 获取 agent session 完整数据：prompts、responses、tool calls；可接入 event collector、SIEM 或 Microsoft Purview；REST API 可拉取最近 48 小时记录。

**意义**：企业审计从"看最终 PR/diff"升级为"看完整运行轨迹"。agent 调了什么工具、为什么花钱、是否访问敏感资源，会成为强需求。

**覆盖日期**：7/3、7/4。

#### 2.1.6 Copilot AI Credit Session Limits

**核心**：2026-07-01 发布。Copilot CLI 和 SDK 可对单个 agent session 设 AI credit 上限；消耗统计覆盖 model calls、subagents、后台 compaction 等整个 session；达到上限后 agent 收尾并提示，而非无限跑。

**意义**：预算成为 agent loop 的停止条件。

**覆盖日期**：7/3、7/4。

#### 2.1.7 Copilot usage metrics API 持续完善

**里程碑**：
- 6/19 增加 `ai_credits_used`，企业/组织可按 single-day 与 28-day user-level 查询。（6/24 重提）
- 6/24 Copilot Free 和 Student plans 改为默认且唯一使用 auto model selection。
- 6/26 `totals_by_ai_adoption_phase` 增加 `total_pull_requests_merged`，从 per-user average 扩展到 PR merge 总量。
- 7/2 修复 CLI 之前不报告 suggested lines of code 的问题；IDE 与插件版本从前只能 server-side telemetry 识别的用户现在能被识别；修复一些真实使用却显示 `0.0` credits 的情况。

**意义**：企业评估 coding agent 从"用了多少 token"升级到"是否提高 PR merge throughput"。

**覆盖日期**：6/24、6/25、6/26、6/27、6/28、6/29、7/2、7/3、7/4。

#### 2.1.8 Copilot Code Review：复用 CLI/SDK 文件工具

**核心**：2026-06-25 更新。Copilot code review 路径开始复用 Copilot CLI / SDK 内置的 `grep`、`rg`、`glob`、`view` 文件探索工具，替代旧的自定义探索工具。GitHub 称在保持 review 质量的同时成本降约 **20%**。Medium analysis depth 增加组织级默认设置与 PR overview 标识。

**意义**：成本优化不只是换便宜模型，更是优化 tool path、检索策略、上下文装载方式。

**覆盖日期**：6/26、6/27、6/28、6/29、7/4。

#### 2.1.9 GitHub Desktop 3.6：worktree + Copilot commit/merge

**核心**：2026-06-26 发布。新增 Git worktree 支持；Copilot 用于 commit message 生成和 merge conflict 辅助解决；Desktop 的 Copilot 功能基于 Copilot SDK，支持 model picker 和 BYOK，可接第三方 provider 或本地模型；commit 生成读取 `.github/copilot-instructions.md` 和 `AGENTS.md`。

**意义**：worktree 从 agent 内部实现细节变成桌面端一等交互对象。未来 coding agent 多任务并行的默认形态就是"每个任务一个 worktree"。

**覆盖日期**：6/26、6/27、6/28、6/29、6/30。

#### 2.1.10 strictKnownMarketplaces（public preview）

**核心**：2026-06-25 推出。企业可在 managed `settings.json` 指定允许的插件 marketplace；Copilot CLI 和 VS Code 只能安装企业显式定义来源里的插件；定位是工具执行前降低不可信插件安装风险的 client governance 能力。

**意义**：MCP、skills、plugins 增多后，"工具从哪里来"会成为和 npm registry、Docker registry 一样重要的安全策略。

**覆盖日期**：6/26、6/27、6/28、6/29。

#### 2.1.11 Copilot 成本中心 enterprise teams / AI credit pool

**里程碑**：
- 6/25：cost centers 支持 enterprise teams，成员使用量自动归因到对应成本中心；SCIM 同步变化时归因自动更新。预算和 usage caps 附着在 cost center 本身。
- 6/30：企业管理员可给 cost center 设 **user-level AI credit budget**，应用到 cost center 内每个成员，随 enterprise team 成员变化自动同步。统计所有 AI credits（included usage pool + additional usage）。当前通过 REST API 创建，Billing UI 后续支持。
- 7/2：cost centers 支持 **AI credit pools**，可限制某 cost center 从企业共享 monthly included AI credits 中消耗多少。Pool 与 budget 不同：前者管 included usage pool，后者管超出后的 metered spend。

**意义**：Agent loop、subagent、长任务、自动化会放大成本。企业会按 team / repo / goal / agent role 拆分。

**覆盖日期**：6/25、6/26、6/27、6/28、6/29、6/30、7/1、7/2、7/3、7/4。

#### 2.1.12 Copilot Agent 进入 JetBrains AI Assistant

**核心**：2026-06-30 GA。Copilot Agent 成为 JetBrains AI Assistant agent picker 的一等选项。可在 AI chat 中选 GitHub Copilot 为 active agent，选 model 和 reasoning depth，把多步骤编码任务交给 Copilot（理解项目、提修改、跑命令、迭代）。后续会推进 NES、Skills、更深工具编排。

**意义**：IDE 变成 **agent provider host**：同一个 IDE 可承载多个 agent。

**覆盖日期**：7/1、7/4。

#### 2.1.13 Copilot for JetBrains：组织级 agents + Claude provider + per-turn credits

**核心**：2026-06-22 更新。支持组织/企业级 custom agents；Copilot CLI 长任务运行中支持 `Add to Queue`、`Steer with Message`、`Stop and Send`；新增 Agent Debug logs summary；Claude 作为 agent provider 进入 public preview；显示 per-turn AI credits。Cloud agent 已 GA，但 Claude agent 当前以 bypass permissions mode 运行（文件编辑和工具调用自动批准），未来才有可配置权限。

**意义**：agent 产品控制面板清单：组织统一下发 agent、中途 steering、调试摘要、成本显示、多 agent provider。

**覆盖日期**：6/24。

#### 2.1.14 Copilot Browser Tools for VS Code GA

**核心**：2026-07-02 GA。Agent 可在浏览器里执行低风险操作；摄像头、麦克风、位置、通知、读取剪贴板等敏感权限不会自动授予，必须用户显式批准，agent 不能代替用户批准。

**意义**：Coding agent 从 terminal/file 扩展到 browser runtime。

**覆盖日期**：7/2、7/4。

#### 2.1.15 Copilot Vision GA

**核心**：2026-07-01 GA。用户可把图片和 PDF 直接附加到 chat prompt；支持 VS Code ask/plan/agent modes、github.com Copilot Chat、Copilot CLI。Business/Enterprise 下，GitHub 保留附件约 24 小时以提供服务。

**意义**：Agent 输入不再只是代码和终端。UX 截图、设计稿、报错截图、PDF 规格文档、架构图都会进入上下文。

**意义**：Coding agent 从"改代码"进入"项目管理编排"。`/goal` 不只拆任务，还能自动创建 issue、设置优先级、估算 effort、安排 target date。

**覆盖日期**：7/2。

- 6/29：Claude Opus 4.8 fast mode 在 Copilot 中滚动预览，面向 Pro+、Max、Business、Enterprise，覆盖 VS Code、Visual Studio、Copilot CLI、cloud agent、App、github.com、Mobile、JetBrains、Xcode、Eclipse。Business/Enterprise 管理员需显式开启策略。

**意义**：Coding agent 模型层会持续变化，产品不能把能力/价格/延迟/权限策略写死在某个模型名上。

**覆盖日期**：6/29、6/30。

#### 2.1.18 MAI-Code-1-Flash GA

**核心**：2026-06-26 GA。Microsoft AI 内部 coding model **MAI-Code-1-Flash** 对 Copilot Business 和 Enterprise 正式 GA。定位低延迟、高频、迭代式 agentic coding workflow 适用模型；按 provider list pricing 纳入 usage-based billing；管理员需在 Copilot settings 启用对应策略。

**意义**：多模型路由不只是"强 vs 弱"，而是按任务阶段拆分（规划、搜索、改代码、review、QA、总结）。

**覆盖日期**：6/27、6/28、6/29。

#### 2.1.19 Kimi K2.7 Code：首个 open-weight 可选模型

**意义**：Open-weight 模型进入主流 coding agent 产品，"低成本、可替换、可路由"模型层越来越重要。

**覆盖日期**：7/2、7/4。

### 2.2 OpenAI Codex CLI

#### 2.2.1 0.142.x 稳定线：MCP tool search 默认启用，代理与远端路径继续补齐

**里程碑**：

- 0.142.1 增加 Windows system proxy auth 支持。
- 6/26 发布 **0.142.3**，相对 0.142.2 没有用户可见变化的 maintenance-only patch。
- 7/1 发布 **0.142.5**，修复 Responses WebSocket request payload 被写入 trace logs 的问题。

## 三、Agent Runtime 核心能力

> 把第二章按产品罗列的能力抽出来，按"能力维度"重新组织。每一节给出当前业界共识方向、设计要点、可行动模板。具体代码示例见第八章「统一示例集」。

### 3.1 任务级模型路由

**业界共识**：
- GitHub Copilot CLI Auto（7/1 GA）按任务复杂度、推理需求、工具编排需求、模型健康信号、cache 边界选模型；
- MAI-Code-1-Flash（6/26 GA）定位低延迟、高频 agentic coding；
- Kimi K2.7 Code（7/1 GA）作为 Copilot 首个 open-weight 可选模型，承担低成本搜索/总结/简单编辑；
- Sonnet 5（6/30 GA）成为 Claude Code 默认执行层；
- Z.ai ZCode + GLM-5.2 给 Cursor/Copilot/Claude Code/Codex 带来价格压力。

**设计要点**：
1. 把"模型选择"从用户菜单升级为 runtime scheduler 职责：`task → model → tools → permission → budget → verification`。
2. 任务角色分层：planner / searcher / builder / reviewer / qa / summarizer。
3. 模型族层 tiers：`cheap_open_weight` / `strong_coding` / `strong_review`。
4. 必须支持"模型别名 + 弃用迁移"（如 Opus 4.6 fast → 4.8 fast），不要把能力/价格/延迟写死在模型名上。
5. Router 输出 `reason` 字段，解释为什么选、预计成本、fallback 模型、是否命中缓存。

**覆盖日期**：6/26、6/27、6/28、6/29、6/30、7/1、7/2、7/3、7/4。

### 3.4 Session checkpoint / rewind

## 四、权限与安全

### 4.1 命令安全分类器与记录

**业界共识**：
- Claude Code v2.1.193（6/27）`autoMode.classifyAllShell`，让所有 Bash/PowerShell 命令都走 auto-mode classifier；denial reasons 写入 transcript、denial toast 和 `/permissions` recent denials。

- Claude Code v2.1.187 加入 `sandbox.credentials`，阻止沙箱命令读取凭据文件和 secret 环境变量。

**设计要点**：
1. 命令执行日志强制记录：`command / risk / decision / classifier_reason / user_override`。
2. Risk 字段标准化：`read / test / build / mutate / destructive / deploy / secret`。
3. Decision 字段：`allow / ask / deny`。
4. 沙箱默认拒绝访问 `~/.aws/credentials`、`~/.ssh`、`*TOKEN*` 环境变量、`.env` 文件。
5. 拒绝原因一律写入 transcript，禁止 silent swallow。

**覆盖日期**：6/24、6/26、6/27、6/28、6/29、6/30、7/1、7/2、7/4。

### 4.2 MCP 信任边界

**业界共识**：见 3.2。Claude Code v2.1.196 不再自动批准仓库提交的 `.mcp.json` 和 `.claude/settings.json`；GitHub `strictKnownMarketplaces` 在企业 `settings.json` 中限制来源；OpenCode MCP auth scope 按 server URL 隔离。

**设计要点**：

```
mcp_trust:
  repo_committed_config:    pending_approval  # 仓库自带配置 ≠ 自动信任
  user_local_config:        trusted
  enterprise_registry:      trusted
  unknown_marketplace:      deny
  auth_scope:               per_server_url
```

1. MCP 配置来源决定默认信任级别，而不是工具剂量。
2. 仓库级配置必须停在 pending approval，避免攻击者通过 PR 带 `.mcp.json` 进来。
3. MCP server OAuth scope 按 server URL 隔离，避免一个 server 拿到所有 token。
4. Failure mode：临时网络错误要重试 + backoff，但不能用作"自动批准"理由。

**覆盖日期**：6/25、6/26、6/27、6/28、6/29、6/30、7/1、7/2、7/4。

### 4.3 Setup-chain 安全

**业界共识**：Mozilla 0din（6/28 报道）展示"干净 GitHub 仓库"如何诱导 Claude Code 运行恶意链路：仓库 README 引导初始化 Python 环境；假 Axiom 脚本报错；Claude 为"修复问题"运行看似正常命令；最终通过 DNS TXT 记录取 payload 并开 reverse shell。结论是 agent 不能只照步骤执行，而要检查"实际会运行什么"。

**意义**：这不是传统 prompt injection，而是 **setup-chain attack**——README、脚本、DNS、shell 命令组合起来绕过静态扫描。

**设计要点**：

```
setup_chain_safety:
  inspect_before_run:
    - package_scripts
    - shell_scripts
    - dockerfiles
    - github_actions
    - curl_or_wget
    - dns_txt_lookup
    - postinstall_hooks

  require_approval_for:
    - dynamic_download
    - network_shell_execution
    - unknown_domain
    - credential_access

  block_by_default:
    - dns_txt_payload
    - curl_pipe_shell
    - hidden_postinstall
    - unknown_binary_download
    - credential_file_access

  warn_before_run:
    - npm_postinstall
    - python_setup_script
    - docker_build_with_network
    - github_action_from_tag
```

**覆盖日期**：6/29、6/30、7/1、7/2、7/3、7/4。

### 4.4 供应链安全（GitHub Actions / npm / runner）

**业界共识**：
- 6/24 simonecorsi/mawesome GitHub Action 被 compromise，攻击者 force-push 恶意 commit 并重指向多个 tags；
- 6/24 codfish/semantic-release-action 被 compromise，force-push + 重指向 16 个 tags（v2/v3/v4/v5 等 floating major tags），使用这些 tag 的 workflow 在 runner 执行攻击者代码；StepSecurity 同日也记录这两起事件；
- 6/25 Leo Platform 生态 20 个 npm 包被投毒，携带窃取 GitHub Actions runner、云凭证、包注册表和密码管理器 secrets 的 toolkit；
- OpenAI Codex 工具（>29,000 下载）曾被发现与窃取 npm auth token 的恶意供应链攻击相关。

**设计要点**：

```
supply_chain:
  github_actions:
    require_sha_pinning: true
    detect_tag_drift: true
    block_unknown_actions: true
  packages:
    cooldown_new_versions_hours: 24
    block_typosquatting: true
    block_known_compromised: true
  runner:
    restrict_egress: true
    redact_secrets_in_logs: true
```

1. Agent 会自动改 workflow、跑 CI、发布 npm 包；一旦供应链入口被劫持，agent 自动化会放大攻击速度。
2. CI runner egress 默认限制，只允许 approved registry。
3. GitHub Actions 必须按 commit SHA pin，检测 tag drift（floating major tag 是常见陷阱）。
4. 新发布的 npm 包加 24 小时 cooldown，避免新投毒包被立即 install。

**覆盖日期**：6/24、6/25、6/26、6/28、6/29、6/30、7/1、7/2、7/3、7/4。

### 4.5 CI/CD 中的 agent 安全

**业界共识**：Copilot CLI 7/2 可用 `GITHUB_TOKEN` 跑进 GitHub Actions，把 agent 带进 CI workflow；同时 runner token、workflow 权限、依赖供应链风险同步放大。

**设计要点**：

```yaml
# .agent/workflows/*.yaml -> GitHub Actions
permissions:
  contents: write
  pull-requests: write
  copilot-requests: write

agent:
  branch_prefix: agent/
  open_draft_pr: true            # 默认只开 draft PR，不直接 merge
  max_ai_credits: 20
  max_runtime_minutes: 30
  allowed_tools: [read, grep, edit, test]
  network_egress: restricted
```

1. CI-safe agent runner 必须默认最小权限 + 预算 + 时长 + branch 隔离 + 只开 draft PR。
2. `GITHUB_TOKEN` scope 严格按 workflow 配置，不要 inject 全组织 PAT。
3. 任何 install/setup 命令先走 `setup_chain_safety` 扫描。
4. Long-running agent 在 CI 里有 stream idle watchdog（5 分钟超时 abort+retry）。

**覆盖日期**：7/3、7/4。

### 4.6 Tracing 防泄漏 + Telemetry manifest

**业界共识**：
- Codex 0.142.5（7/1）修复 Responses WebSocket request payload 被写入 trace logs 的问题；
- Qwen Code v0.19.5 worker stderr credential redaction；
- Alibaba 7/3 禁用 Claude Code，原因与"环境监测特性可帮助识别 China-linked users"相关；
- Claude Code v2.1.187 sandbox.credentials 阻止沙箱读取凭据文件。

**设计要点**：

```
tracing:
  default: metadata_only
  never_log:
    - full_prompt
    - full_tool_output
    - secrets
    - env
    - auth_headers
    - websocket_request_payload
  log_allowed:
    - tool_name
    - exit_code
    - duration_ms
    - payload_digest
    - token_count

telemetry:
  mode: enterprise_off_by_default
  collect: [version, platform, anonymized_error_code]
  never_collect:
    - file_content
    - secrets
    - proxy_url
    - timezone_as_identity_signal
    - repo_secrets
    - full_prompt
    - full_tool_output
  enterprise_disable: true
  export: [jsonl, otel, siem_webhook]
```

1. Tracing 默认只记录 metadata，不记录完整 prompt / tool output / request payload；要记录完整内容必须显式 debug consent。
2. Telemetry manifest 公开声明会采集什么、不会采集什么；enterprise mode 必须可关闭。
3. 时区、代理 URL、本地用户路径等间接身份证信号也列在 `never_collect`。

**覆盖日期**：6/24、7/2、7/3、7/4。

## 五、成本治理

### 5.1 AI credits / session limits / cost center / team budget

**业界共识**（聚合第二章 §2.1.6 / §2.1.11）：
- 6/25 cost centers 支持 enterprise teams / SCIM 自动归因；
- 6/30 cost centers 支持 user-level AI credit budget；

- Gartner 预测（TechRadar 6/25）：AI coding tools 的成本可能在 2028 年超过平均开发者薪资。

**设计要点**：

3. Session budget 是 agent loop 的停止条件，不是事后账单功能。
4. Cost center 名 + AI credit pool 名要随 SCIM 同步自动更新；硬停止 `hard_stop_when_pool_exhausted: true`。

### 5.2 Cost Trace：按 goal / team / role / surface 拆分

- Enterprise 会要求按 repo / team / goal / agent role / surface 拆分。

**设计要点**：

```json
{
  "goal_id": "goal_001",
  "team": "agent-runtime-dev",
  "cost_center": "engineering-ai",
  "surface": "github_actions | cli | tui | web | desktop | daemon",

}
```

1. Cost Trace 仪表盘不只显示总 token，要显示"谁烧的、为什么烧、是否有产出"。
2. outcome 同步记录：`pull_request_created / pull_request_merged / tests_passed / human_review_required`。
3. Cost per merged PR 比 token per user 更接近真实 ROI。

**覆盖日期**：6/24、6/25、6/30、7/1、7/2、7/3、7/4。

### 5.3 Tool-path 优化降本

**业界共识**：

## 六、验证与可观测

### 6.1 Verification Stack（critic / review / qa / iterate）

**业界共识**：OpenHands 6/22 把 verification 分两层 + iterate skill：
- L1：agent-level critic 在代码 push 前评估 agent trajectory；
- L2：repo-level verifier = code review agent（读 diff，捕捉 style/security/data structure 问题）+ QA agent（运行软件、模拟用户、发 API 请求，输出带证据 QA 报告）；
- `/iterate` skill：自动运行验证 → 修复 → 再 push → 直到 PR 干净。

**核心论点**：AI 生成代码已变便宜；瓶颈是验证。OpenHands 公开文档宣称 next generation agent platform。

**设计要点**：

```
verification:
  pre_push:
    - no_unapproved_destructive_command
    - no_secret_leak
    - build_passed

  pull_request:
    - review_agent
    - qa_runner
    - dependency_risk_check

  iterate:
    max_rounds: 3
    stop_when:
      - tests_passed
      - qa_passed
      - no_blocking_review_comments
```

**覆盖日期**：6/24、6/25、6/26、6/27、6/28、6/29、6/30、7/2、7/4。

### 6.2 RuntimeEventStream 与企业审计

**业界共识**：GitHub 7/2 推出 Copilot agent session streaming public preview——企业可跨 Copilot clients 获取 agent session 数据，包括 prompts、responses、tool calls；数据通过 streaming endpoint 接入 event collector、SIEM 或 Microsoft Purview；REST API 可拉取最近 48 小时。

**意义**：Agent 审计已经成为企业采购的硬门槛。未来企业不会只问"agent 能不能写代码"，会问"agent 做过什么、花了多少钱、有没有访问敏感资源、是否能进 SIEM"。

**设计要点**：

## 七、深度趋势与机会

把 18 期简报里反复出现的趋势收敛成 5 条主线。每条给出现象、机会、对 allthecodes 这类新进 agent 项目的可行动切入。

### 趋势 A：从"单 agent 聊天框"走向"并发 agent + skills + 后台执行"

**现象**：
- OpenAI/Columbia/Duke/UPenn Codex 使用研究：2026 上半年活跃用户 5x、>10% 用户每周某时点管理 3+ 并发 Codex agents、26.6% 使用 skills；复杂任务请求比例显著上升。
- Claude Code v2.1.198 后台 agent 在 worktree 中完成代码工作后自动 commit/push/open draft PR；与 GitHub Issue Fields (7/2) 结合后形成 `issue → worktree → background agent → draft PR → verification → human merge` 闭环。
- Codex 0.143 alpha、Qwen Code v0.19.6 都在做 nested subagents、session artifact、daemon activity status、filler PR gate。

**机会**：不要只优化"一个聊天窗口"。优先做并发 session、worktree、skill registry、queue、status board、per-task budget、background agent 状态机。

**覆盖日期**：6/26、6/27、6/28、6/30、7/1、7/2、7/3、7/4。

### 趋势 B：成本治理会成为企业购买 agent 的核心条件

**现象**：
- Gartner 预测（TechRadar 6/25）：AI coding tools 成本可能在 2028 年超过平均开发者薪资；token discipline 不会自然出现，需组织治理。
- GitHub 6/25–7/2 持续推进 cost center enterprise teams → user-level AI credit budget → AI credit pools。
- Codex 6/30 后台 auto-review 异常消耗事件暴露隐性成本风险。
- Copilot CLI Auto 7/1 沿 cache boundary 路由降低缓存成本，Auto 用户享 10% multiplier 折扣。

**机会**：Cost Trace 是产品差异化点。按 `repo / team / goal / agent_role / model / tool_path / surface / user_or_workflow` 拆分，硬停止策略、内部预算转账、随 SCIM 同步。

**覆盖日期**：6/25、6/26、6/27、6/28、6/30、7/1、7/2、7/3、7/4。

### 趋势 C：开源供应链中的 AI agent 痕迹被严重低估

**现象**：6/23 论文扫 1.8 亿 Git 仓库，bot-account lookup 仅恢复 28,154 个 Claude Code commits（3.3%），多方法检测识别 850,157 个；commit-attributed agents 每月产生超过 320,000 个 commits。

**机会**：内置 `provenance header`——agent、模型、session、人类发起者、review 状态、测试证据都写入 PR/commit/session report，方便未来供应链审计。可以做"AI 代码生产证据链"作为核心卖点。

**覆盖日期**：6/23、6/24、6/25、6/26、6/27、6/28、6/30、7/1、7/2、7/3、7/4。

### 趋势 D：Verification 比生成更稀缺

**现象**：
- OpenHands Verification Stack（6/22）+ Agent Canvas（覆盖：6/24–7/4）把 QA agent 放进 verification 第二层、iterate skill 自动循环。
- Microsoft 7/1 研究：CLI coding agent 采用者合并 PR 比 counterfactual 多 24%。
- Cursor 6/28 数据：AI 代码无单独 review 进入生产的比例 7% → 36.3%。

**机会**：高价值卖点不是"能改代码"，而是"能证明改得对"。最小验证栈：`build / test / lint / browser smoke / API smoke / security gate`。把 evidence、risk、unverified assumptions 自动写入 Session Report。

**覆盖日期**：6/22、6/24、6/26、6/28、6/30、7/1、7/2、7/3、7/4。

### 趋势 E：安全焦点从"模型拒绝 prompt"扩展到"执行链 + 工具来源 + 供应商信任"

**现象**：
- Mozilla 0din（6/28）展示 setup-chain attack：干净仓库通过 README + 脚本 + DNS TXT 拉取 payload + reverse shell。
- codfish/semantic-release-action 6/24 被劫持；simonecorsi/mawesome 6/24 被劫持；Leo 平台 6/25 20 个 npm 包被投毒。
- Alibaba 7/3 禁用 Claude Code（环境监测特性识别 China-linked users）。
- Claude Code v2.1.196 把仓库 `.mcp.json` 改为 pending approval；v2.1.200 default permission mode 改为 Manual；`strictKnownMarketplaces` (6/25) 治理插件来源。
- Codex 0.142.5 修复 WebSocket request payload 写入 trace logs 的问题。

**机会**：把"安全可验证 agent runtime"做成核心定位——默认开启 setup-chain scan + supply-chain gate + session report + provenance + telemetry manifest + enterprise off-by-default。

**覆盖日期**：6/24、6/25、6/26、6/27、6/29、6/30、7/2、7/3、7/4。

### 补充趋势

- **F1：Loop engineering 取代 prompt engineering**（BusinessInsider 6/22 概念）。Agent 产品的护城河不是"prompt 写得好"，而是 state、permissions、rollback、tool isolation、cost、release governance 这些 runtime 细节。
- **F2：UI 多入口 + Runtime 单核**。Copilot Agent 6/30 进入 JetBrains AI Assistant；OpenCode v1.17.13 桌面端 + SDK + release attestation；Qwen Code v0.19.5 daemon-direct 让 Chrome extension / Desktop / daemon 共用 runtime。Coding agent UI 不再是一个聊天框，而是 IDE / CLI / Web / Desktop / Mobile / Browser extension 全覆盖。
- **F3：国际地缘政治影响 agent 采用**。Anthropic vs Alibaba 双向限制 → 企业采购会按供应商、遥测、地域、数据边界来评估，不只是能力强弱。Enterprise mode（本地模型 / 本地日志 / telemetry off / MCP allowlist / provider policy / 审计导出）会成为产品差异化点。
- **F4：开发者形态变化**。Anthropic 工程负责人在 BusinessInsider 6/18 报道中提到 Claude Code 让程序员更孤独；GitHub 在 6 月因 AI coding 创造历史最佳月度业绩（BusinessInsider 6/27 报道）。
