PTY scope and user-directed skip

The final validation set intentionally excluded pty_tui_e2e after the user directed “skip PTY tests”. Before the final IPC-only compatibility commit, two complete PTY runs on this branch each passed 215 tests with 36 ignored (1924.92s and 1930.03s). Those runs are historical evidence only; this artifact does not claim a fresh final Web IPC PTY integration gate.

Failure discovery and recovery

  1. The first repository-wide run passed PTY, then exposed four deterministic daemon failures. Loopback Team Memory traffic was incorrectly inheriting HTTP_PROXY, and a new submit inherited the previous engine abort. Commit 71bb6768 fixed both; daemon then passed 196/196.
  2. The next run passed PTY and daemon, then exposed an IPC hang. Explicit JSON null security was rejected as a non-Optional structure; the spawned request task panicked while another sender clone kept the receiver open. Commit 46b22cad added missing/null compatibility, moved adapter conversion before pending registration, and bounded test receives.
  3. The final PTY run was stopped at the user's request. A complete explicit non-PTY target set then returned exit 0.
