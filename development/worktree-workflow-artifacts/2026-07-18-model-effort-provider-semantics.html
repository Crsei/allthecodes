Model-Effort Provider Semantics Fix

让 effort / reasoning 配置在 Anthropic 与 Codex 两条 provider 路径上语义自洽
Worktree: .worktrees/model-effort-provider-semantics Branch: worktree/model-effort-provider-semantics Plan: 2026-07-18-model-effort-provider-semantics-fix-plan.md Artifact date: 2026-07-18

任务目标

把 effort_value / model_reasoning_effort / output_config.effort / effort_level / effort_to_budget_tokens 等多个 effort / reasoning 相关字段 在 Anthropic 与 Codex 两个 provider 路径上的混淆（"转移 / 跨污染 / 漂移 / 静默丢"）一次性对齐。 根因是历史代码把 Codex 的 reasoning.effort 与 Anthropic 的 thinking.budget_tokens 和 output_config.effort 塞进同一套字段与回退链， 导致 TUI 显示、wire 请求、settings 持久化三者语义不一致。

权威计划： development/tui/2026-07-18-model-effort-provider-semantics-fix-plan.md
对各个 identifier 的全量审计见 development/archive/effort-family-audit-2026-07-18.md（子代理产物，已合入参考材料）。

流程步骤（按 Phase 顺序）

  • Phase A — 优先级反转/静默丢之类的失败测试与 KNOWN_ISSUES 条目（EFFORT-001..006）。
  • Phase B — 在 allthecodes_engine::effort 集中 effort 语义：单一 resolver (resolve_effort_for_state)、CapabilityProvenance 与 EffortTransport 枚举、 统一 effort_value → output_config → effort_level 回退链。
  • Phase C — provider-specific 命令与持久化：Codex /effort 路径只写 authProfiles..modelReasoningEffort，停止触碰 root output_config.effort；/effort auto 不再持久化具体档。
  • Phase D — TUI 显示：picker / statusline / status widget 改用 resolver； "X tokens" 文案被 gating 到 Anthropic 固定 budget 传输通道；picker 标注 source provenance。
  • Phase E — 内置 Codex catalog 添加 version/source/updated provenance 常量与访问器； 更新 codex-backend.md、settings JSON schema 的字段说明、KNOWN_ISSUES 条目与本 artifact。
