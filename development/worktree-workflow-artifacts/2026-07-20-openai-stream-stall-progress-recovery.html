OpenAI stream stall progress recovery

Task goal

Correct the follow-up regression where a long-reasoning OpenAI/Codex stream resumed after 76121 ms but the query loop rejected the newly arrived progress as stream stalled, then retried a second stream that also did not finish before the session ended.

Plan source

development/runtime/2026-07-19-openai-stream-timeout-recovery-plan.md, section “2026-07-20 stall-progress regression follow-up”. The follow-up plan was committed on the main branch before this worktree was created.

Live evidence

  • Session/run: ddc64e0a-e103-43ec-8a37-dbd5f784a65d.
  • At 2026-07-19T16:00:51.662768Z, the first request failed with stream stalled for 76121ms without progress.
  • The same-model retry started immediately and established HTTP 200 SSE at 16:00:54.815274Z, but no model_request_finish was recorded before session_end at 16:02:25.785742Z.
  • The old watchdog checked elapsed stall time only when a genuine progress event arrived. It therefore rejected recovery instead of accepting it.

Implemented correction

  • MessageStart, content block events, message delta, and message stop are all treated as semantic stream progress.
  • Every real progress event is accepted first and resets last_progress_at, regardless of the preceding pause length.
  • The stall comparison is restricted to non-progress events; the independent idle timeout still guards a stream whose next semantic event never arrives.
  • The regression test delays both the initial MessageStart and the following content event by 40 ms with a 25 ms test stall threshold, and verifies one successful request with assistant text Recovered.
